# НМТ Практика

Сайт для проходження симуляцій НМТ з математики: підготовка, тест із таймером, збереження відповідей,
результат і розбір кожного завдання з текстовим розв’язком і відеопоясненням.

Статичний сайт (React + TypeScript + Vite). Сервер, база даних і реєстрація не потрібні: прогрес зберігається в браузері.

## Швидкий старт

Потрібен Node.js 20+.

```bash
npm install          # встановлення (версії зафіксовані в package.json)
npm run dev          # розробка: http://localhost:5173
npm test             # автоматичні перевірки (оцінювання, числа, дедлайн, імпорт, сховище)
npm run build        # перевірка вмісту + TypeScript + production-збірка в dist/
npm run preview      # перегляд зібраного сайту
npm run e2e          # наскрізна перевірка в Chromium (після build), знімки в e2e-shots/
```

## Назва

Змінюється в одному місці — `src/config.ts` → `appName`. Заголовок вкладки береться звідти ж
(статичний `<title>` в `index.html` — лише до завантаження сторінки).

## Набори завдань

Формат описано в [docs/CONTENT.md](docs/CONTENT.md), схеми — `docs/content.schema.json` і `docs/video-map.schema.json`.

Зараз підключено:

| Набір | Стан |
|---|---|
| `nmt-23` «Симуляція НМТ №23» | 22 завдання з PDF власника сайту; рисунки перемальовано у SVG. Генерується скриптом `scripts/generate-nmt-23.py`. Довідник — сторінки від власника, таблиця переведення — 2025 р. |
| `nmt-3` «Симуляція НМТ №3» | 22 завдання й ключі від власника сайту; рисунки намальовано у SVG. Генерується скриптом `scripts/generate-nmt-3.py`. Довідник і таблиця переведення — як у №23. |

### Імпорт набору

1. Підготуйте папку: `package.json`, за потреби `video-map.json`, `assets/`, `reference/`.
2. `npm run content:import -- ./шлях/до/папки` — набір перевіряється; при будь-якій помилці нічого не копіюється,
   а в повідомленні вказано запис і поле. Вміст не виправляється автоматично.
3. `npm run content:report` — звіт про готовність: скільки умов, ключів, розв’язків, відео, чи є довідник і таблиця переведення.

Для симуляції №23 використовуйте `id: "nmt-23"` — тоді запис у каталозі заміниться на справжній набір.
При будь-якій зміні умов чи ключів збільшуйте `simulation.version`: уже завершені спроби залишаться з тією версією, з якою їх пройдено.

### Довідник (PDF)

Покладіть файл у `public/content/sets/<id>/reference/` і опишіть у `referenceMaterials`:
`{"id":"ref","title":"Довідкові матеріали","kind":"pdf","src":"reference/file.pdf","downloadable":true}`.
Кількість сторінок визначається з файла. Без довідника сайт пише «Довідкові матеріали ще не додано».
Перевірте, що в довіднику немає розв’язків поточного тесту.

### Таблиця переведення 100–200

Лише офіційна таблиця з роком і джерелом (`conversionTables`, див. docs/CONTENT.md). Лінійних формул і вигаданих порогів немає:
без таблиці показується первинний бал і «Таблицю переведення ще не додано».

## Відео

Кожне відео прив’язується до конкретного `questionId` у `video-map.json`.

- **Локально (розробка):** покладіть файли в `./media/` (папка в `.gitignore`) і вкажіть `localPath`, напр. `"nmt23/q01.mp4"`.
  `npm run dev` і `npm run preview` віддають їх за адресою `<base>media/…` (з підтримкою перемотування).
  Інша адреса локального медіасервера — змінна `VITE_MEDIA_BASE_URL`.
  Шлях на комп’ютері не є публічною адресою: на опублікованому сайті такі відео не відкриються.
- **Публікація:** завантажте відео у вибране сховище/CDN (наприклад, Cloudflare R2, Bunny, S3) і вкажіть `publicUrl: "https://…"`.
  Також підтримуються вбудовані плеєри YouTube (youtube-nocookie) і Vimeo (`kind: "embed"`).
  HLS не підключено (поки немає потреби); для нього знадобиться окремий програвач.
- Не кладіть багатогігабайтні відео в Git. `content:import` не копіює відеофайли.
- Відео й розв’язки показуються лише після завершення спроби. Плеєр завантажується ліниво, без автозапуску; при старті іншого відео попереднє ставиться на паузу.

## Публікація

`npm run build` створює `dist/`. Базовий шлях за замовчуванням відносний (`./`), а маршрутизація — через `#/…`,
тож сайт працює в корені домену, у підпапці й на GitHub Pages без додаткових налаштувань.
Для абсолютного базового шляху: `VITE_BASE=/nmt/ npm run build`.

Підійде будь-який статичний хостинг: GitHub Pages, Netlify, Cloudflare Pages, Vercel (папка `dist`).

## Як влаштовано

```
src/
  config.ts            назва, шляхи
  content/             типи вмісту, перевірка імпорту, безпечні адреси, текстовий формат
  engine/              рушій спроби, оцінювання, числа, сховище, вкладки (без React)
  machine.ts           явна модель станів: prepare → active → review; оверлеї selector / reference / finishConfirm
  router.ts            hash-маршрути: #/sim/<id>, #/attempt/<id>/q/<n>, #/attempt/<id>/review
  ui/                  екрани й компоненти
public/content/        каталог і набори
scripts/               перевірка, звіт, імпорт, генерація демонабору й демо-PDF, e2e
tests/                 автоматичні перевірки (Vitest)
```

Ключові правила рушія:

- Таймер рахується від абсолютних `startedAt` / `deadlineAt`; перезавантаження й фонова вкладка не дають зайвого часу, довідник не ставить на паузу.
- Чернетка й збережена відповідь зберігаються окремо; чернетка не є відповіддю.
- Коли час вийшов — автоматичне завершення рівно один раз: зараховуються збережені відповіді й коректні чернетки (правило оголошено на стартовому екрані).
- Завершення ідемпотентне; завершену спробу змінити не можна.
- Одна активна вкладка на спробу; друга вкладка бачить попередження й може «Працювати тут».
- Числа: ціле, десяткове, кома/крапка, звичайний і Unicode-мінус; без `eval`, `NaN`, `Infinity`. Порівняння точне (раціональні числа) або з явно вказаною похибкою.

## Обмеження (чесно)

- **Ключі не приховані.** Це статичний сайт: ключі відповідей містяться в завантажених JSON-файлах, і їх може побачити той, хто аналізує мережевий трафік. Справжній захист потребує серверного оцінювання й видачі розбору після завершення.
- **Таймер локальний.** Це тренажер; від навмисної зміни системного годинника він не захищає.
- **Прогрес лише в цьому браузері.** Очищення даних сайту видаляє спроби; між пристроями прогрес не синхронізується.
- Розбір попередньої спроби залишається доступним під час нової — це не захищається.
